在 Kubernetes 從零部署 Nexus Repository 3：PostgreSQL、PVC 與 Ingress

從命名空間、PostgreSQL、Secret、PVC、StatefulSet、Service 和 Ingress 開始，逐步部署可持久化、可備份、可升級的 Nexus Repository 3。

lucaslz作者
2026年7月11日 9 分鐘閱讀
#Nexus #Kubernetes #PostgreSQL #StatefulSet #Maven
{ }

這篇文章只討論全新部署 Nexus Repository 3，不含 Nexus 2 的資料遷移。先把一套乾淨的 Nexus 3 跑穩，再進入下一篇遷移教學，後續故障排除的界線會清楚很多。

系列導覽：Kubernetes 重建遷移教學系列。本篇是 Nexus 遷移的前置教學。

範例使用單實例 StatefulSet、外部 PostgreSQL 與持久磁碟區。高可用多實例涉及授權與官方 HA 架構，不是把 replicas 從 1 改成 3 那麼簡單。

最終架構

flowchart LR
  A["Maven / npm / Docker 用戶端"] --> B["Ingress 或內部 VIP"]
  B --> C["nexus Service"]
  C --> D["Nexus StatefulSet 單實例"]
  D --> E["PVC /nexus-data"]
  D --> F["PostgreSQL"]
  G["備份任務"] --> E
  G --> F

Nexus 官方容器把設定、日誌與製品資料放在 /nexus-data，容器行程以 UID 200 執行。這個目錄必須持久化且可寫入。參考官方容器映像說明。

第 1 步：確定版本、容量與上下文路徑

先鎖定以下值：

NEXUS_VERSION=<approved-version>
NEXUS_IMAGE=<image-registry>/sonatype/nexus3:${NEXUS_VERSION}
NEXUS_HOST=repo.example.com
NEXUS_CONTEXT=/nexus

不要使用 latest。把映像同步到內部倉庫後記錄 digest：

crane digest "$NEXUS_IMAGE"

容量至少考慮：

  • 目前 hosted 製品總量。
  • proxy 快取的上限與清理策略。
  • 資料庫、日誌、任務的暫存空間。
  • 備份保留週期。
  • 未來一到兩年的成長量。

第 2 步：建立命名空間與 PostgreSQL 資料庫

kubectl create namespace repository-system

PostgreSQL 建議由獨立資料庫平台提供並完成備份。建立專用帳號與資料庫：

CREATE ROLE nexus LOGIN PASSWORD '<generated-password>';
CREATE DATABASE nexus OWNER nexus ENCODING 'UTF8';

驗證 Nexus 節點能連線到資料庫：

kubectl -n repository-system run pg-check --rm -it --restart=Never \
  --image=<approved-postgres-client-image> -- \
  psql 'postgresql://nexus:<password>@<postgres-host>:5432/nexus' \
  -c 'select current_database(), current_user;'

密碼不要出現在 shell history。正式環境使用互動輸入、臨時環境變數或 Secret 管理系統。

第 3 步：建立資料庫 Secret

kubectl -n repository-system create secret generic nexus-database \
  --from-literal=jdbc-url='jdbc:postgresql://<postgres-host>:5432/nexus' \
  --from-literal=username='nexus' \
  --from-literal=password='<generated-password>'

官方支援以環境變數、JVM 參數或屬性檔案設定 PostgreSQL，但不建議混用。在容器環境中，直接使用環境變數最為清楚。參考使用 PostgreSQL 安裝 Nexus Repository。

第 4 步：建立 PVC

存為 00-storage.yaml：

apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: nexus-data
  namespace: repository-system
spec:
  storageClassName: <storage-class>
  accessModes: [ReadWriteOnce]
  resources:
    requests:
      storage: <planned-size>

套用並確認綁定：

kubectl apply -f 00-storage.yaml
kubectl -n repository-system get pvc nexus-data -w

PVC 必須顯示 Bound。如果是靜態本機磁碟區，還要在 Nexus Pod 上加上 nodeAffinity，並把節點故障復原流程寫進 Runbook。

第 5 步：建立 Service

存為 01-service.yaml：

apiVersion: v1
kind: Service
metadata:
  name: nexus
  namespace: repository-system
spec:
  selector:
    app.kubernetes.io/name: nexus
  ports:
    - name: http
      port: 8081
      targetPort: http
kubectl apply -f 01-service.yaml

後續若為 Docker hosted/group 倉庫分配獨立連接埠，應在 Service 與容器連接埠中明確加上，不要與管理連接埠混淆。

第 6 步：建立 StatefulSet

存為 02-statefulset.yaml：

apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: nexus
  namespace: repository-system
spec:
  serviceName: nexus
  replicas: 1
  selector:
    matchLabels:
      app.kubernetes.io/name: nexus
  template:
    metadata:
      labels:
        app.kubernetes.io/name: nexus
    spec:
      terminationGracePeriodSeconds: 120
      securityContext:
        fsGroup: 200
        fsGroupChangePolicy: OnRootMismatch
      containers:
        - name: nexus
          image: <image-registry>/sonatype/nexus3:<approved-version>@sha256:<digest>
          ports:
            - { name: http, containerPort: 8081 }
          env:
            - { name: NEXUS_CONTEXT, value: /nexus }
            - name: NEXUS_DATASTORE_NEXUS_JDBCURL
              valueFrom:
                { secretKeyRef: { name: nexus-database, key: jdbc-url } }
            - name: NEXUS_DATASTORE_NEXUS_USERNAME
              valueFrom:
                { secretKeyRef: { name: nexus-database, key: username } }
            - name: NEXUS_DATASTORE_NEXUS_PASSWORD
              valueFrom:
                { secretKeyRef: { name: nexus-database, key: password } }
            - name: INSTALL4J_ADD_VM_PARAMS
              value: >-
                -Xms2g -Xmx2g -XX:MaxDirectMemorySize=2g
                -Djava.util.prefs.userRoot=/nexus-data/javaprefs
          resources:
            requests: { cpu: "2", memory: 4Gi }
            limits: { cpu: "4", memory: 6Gi }
          startupProbe:
            httpGet: { path: /nexus/service/rest/v1/status, port: http }
            periodSeconds: 10
            timeoutSeconds: 5
            failureThreshold: 60
          readinessProbe:
            httpGet: { path: /nexus/service/rest/v1/status, port: http }
            periodSeconds: 10
            timeoutSeconds: 5
            failureThreshold: 6
          livenessProbe:
            httpGet: { path: /nexus/service/rest/v1/status, port: http }
            periodSeconds: 30
            timeoutSeconds: 5
            failureThreshold: 6
          volumeMounts:
            - { name: data, mountPath: /nexus-data }
      volumes:
        - name: data
          persistentVolumeClaim: { claimName: nexus-data }

資源只是起點，應根據索引規模、並發請求與官方系統需求，壓測後再調整。不要把 JVM 堆直接設成容器記憶體上限。

套用前驗證：

kubectl apply --server-side --dry-run=server -f 02-statefulset.yaml
kubectl apply -f 02-statefulset.yaml
kubectl -n repository-system rollout status statefulset/nexus --timeout=20m

首次啟動可能需要數分鐘。startupProbe 應涵蓋資料庫初始化與外掛程式載入時間，readiness 不應過早放行流量。

第 7 步：排查啟動失敗

kubectl -n repository-system get pod nexus-0 -o wide
kubectl -n repository-system describe pod nexus-0
kubectl -n repository-system logs nexus-0 --tail=300
kubectl -n repository-system get endpointslice \
  -l kubernetes.io/service-name=nexus -o wide

常見原因：

  • PVC 未綁定，或目錄不是 UID 200 可寫。
  • PostgreSQL 位址、帳號或 TLS 參數錯誤。
  • 探針路徑沒有包含 /nexus 上下文。
  • 容器記憶體太小導致 OOMKilled。
  • 資料庫 schema 已被不相容版本初始化。

connection refused 表示連接埠尚未開始監聽；首次啟動期間應查看應用程式日誌，而不是不斷刪除 Pod。

第 8 步：讀取首次管理員密碼

kubectl -n repository-system exec nexus-0 -- \
  sh -c 'test -f /nexus-data/admin.password && cat /nexus-data/admin.password'

第一次登入後：

  1. 立即修改管理員密碼並存到密碼管理工具。
  2. 建立個人管理員帳號，避免共用 admin。
  3. 依安全需求決定是否允許匿名下載。
  4. 設定郵件、稽核與清理任務。
  5. 確認 admin.password 檔案已被 Nexus 刪除或失效。

不要把初始密碼複製進 Wiki、Git 或聊天紀錄。

第 9 步：建立 Ingress

存為 03-ingress.yaml：

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: nexus
  namespace: repository-system
  annotations:
    nginx.ingress.kubernetes.io/proxy-body-size: "0"
    nginx.ingress.kubernetes.io/proxy-read-timeout: "600"
    nginx.ingress.kubernetes.io/proxy-send-timeout: "600"
spec:
  ingressClassName: nginx
  tls:
    - hosts: [repo.example.com]
      secretName: repo-example-com-tls
  rules:
    - host: repo.example.com
      http:
        paths:
          - path: /nexus
            pathType: Prefix
            backend:
              service:
                name: nexus
                port: { number: 8081 }

先不要改公開 DNS，用 --resolve 測試：

curl -kfsS --resolve repo.example.com:443:<ingress-address> \
  https://repo.example.com/nexus/service/rest/v1/status

預期會回傳可用狀態。上傳大型元件前，再確認 Ingress、負載平衡器與 CDN 都沒有請求主體大小限制。

第 10 步：建立 Maven 倉庫並驗證

在 UI 建立：

  • maven-releases：hosted，Version policy 為 Release。
  • maven-snapshots：hosted，Version policy 為 Snapshot。
  • maven-central：proxy，遠端為 Maven Central。
  • maven-public：group，包含以上倉庫。

用戶端倉庫位址：

<repository>
  <id>nexus-public</id>
  <url>https://repo.example.com/nexus/repository/maven-public/</url>
</repository>

發布位址：

<distributionManagement>
  <repository>
    <id>nexus-releases</id>
    <url>https://repo.example.com/nexus/repository/maven-releases/</url>
  </repository>
  <snapshotRepository>
    <id>nexus-snapshots</id>
    <url>https://repo.example.com/nexus/repository/maven-snapshots/</url>
  </snapshotRepository>
</distributionManagement>

憑證放在使用者的 settings.xml 或 CI Secret 中，不要寫進專案 POM。

使用一個臨時的 Maven 專案完成驗證：

mvn -U dependency:get -Dartifact=<group>:<artifact>:<version>
mvn deploy

第 11 步：設定備份與清理任務

備份必須同時涵蓋：

  • PostgreSQL 一致性備份。
  • /nexus-data 中的 blob、設定與金鑰材料。
  • Kubernetes 清單與 Secret 管理系統中的參照。

資料庫與 blob 的備份時間點要協調，否則中繼資料與檔案可能不一致。proxy 快取可設定清理策略，但刪除 hosted 製品時必須有保留與稽核規則。

完成定義

  • StatefulSet 重建後使用同一 PVC 正常還原。
  • PostgreSQL 與 /nexus-data 均完成還原演練。
  • Service、Ingress、TLS 與上下文路徑一致。
  • Maven 下載、Release 發布、Snapshot 發布均成功。
  • 管理員初始密碼已輪換，CI 使用獨立最小權限帳號。
  • 映像版本與 digest 已固定，升級與回滾步驟已記錄。

完成乾淨部署後，再進行 Nexus 2 到 Nexus 3 的資料遷移，不要把「新平台建置」與「歷史資料匯入」混成一次不可回退的操作。
