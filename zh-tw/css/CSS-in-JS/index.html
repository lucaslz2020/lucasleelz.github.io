CSS-in-JS

從關注點分離出發，理解 CSS-in-JS 的設計動機、運作方式與適用場景。

傳統開發模式

一般而言，在 Web 開發中，我們都會將 CSS、HTML、JavaScript 三者分離。

HTML 負責網頁的結構。

CSS 負責網頁上各個元素的顯示樣式（效果）。

JavaScript 負責網頁與使用者的互動（邏輯）。

將電腦程式分隔成不同部分的設計原則，就是關注點分離原則（Separation of concerns，SoC）。因此 HTML、CSS、JavaScript 三者正是關注點分離原則的典型應用。

什麼是 CSS-in-JS

CSS-in-JS 是一種樣式技術，用 JavaScript 撰寫 CSS，也就是把 CSS 整合進 JavaScript 中。這看起來有點反直覺。

執行此 JavaScript 時，會產生 CSS（通常是<style>元素）並附加到 DOM 中。

為什麼會有 CSS-in-JS？

傳統開發中，我們通常直接在 HTML 中引入 CSS 檔案，樣式缺少作用域隔離，很容易發生樣式互相覆蓋的情形。

現代開發逐步走向元件化，希望樣式也能在元件邊界內生效。CSS-in-JS 恰好可以做到「就近管理樣式、減少污染」。

解決作用域問題

使用CSS-in-JS，就能用 JavaScript 作用域模擬 CSS 作用域，讓 CSS 擁有獨立的作用域，阻止 CSS 程式碼外洩到元件外部，避免樣式衝突。樣式只在元件內部生效，藉此解決 CSS 沒有作用域的問題。

增加元件的獨立性與可移植性

移動元件時，我們可能會忘記樣式檔案，甚至不知道樣式檔案在哪裡；使用CSS-in-JS，元件本身就是一個獨立檔案，只要移動元件本身即可。開箱即用，就能輕鬆建立鬆耦合的應用程式。

可重用性

只需要撰寫一次，就能在任何地方執行；元件不僅可以在同一個應用程式中重用，也可以在使用相同框架建置的其他應用程式中重用。

動態性

CSS 缺乏動態性，無法依條件為某個元素加上樣式；使用CSS-in-JS，就能根據 JavaScript 的動態功能為元素動態加上樣式，讓複雜的邏輯也能套用在樣式規則上。特別是建立需要動態功能的複雜 UI 時，它是很理想的解決方案。

按需引入

隨著業務量增加，元件越來越龐大，因此需要按需引入；採用treeshaking的方式，使用CSS-in-JS會更容易做到按需引入。

因此，CSS-in-JS 正是為了解決 CSS 的侷限性，例如缺乏動態功能、作用域與可移植性。
