物件導向與好程式碼

從程式碼品質與可維護性出發，思考物件導向、設計模式與工程能力之間的關係。

如果說資料結構與演算法教你怎麼寫出「算得更快、跑得更穩」的程式碼，那麼物件導向與設計模式更關注「怎麼讓系統更容易維護、更容易擴充」。

在工程實務中，常見的程式碼品質問題往往不是「不會寫程式碼」，而是：

  • 命名表達模糊，意圖看不清楚
  • 類別職責不單一，邊界混亂
  • 分層失衡，耦合度過高
  • 缺乏模組化，改一處會影響太多地方

這些問題會推高成本：線上故障更難排查、修復更慢，團隊長期被「修修補補」拖住。
一旦把這些問題徹底弄懂，系統就會更穩定，團隊也會有更多時間去做更有價值的事。

如果你現在也在做技術面試，針對「設計能力」提問時，不要只問「有沒有聽過某個模式」，更有效的是問「你在什麼情境下這樣做、為什麼這樣設計、後來有什麼收益或代價」。

對於已經帶團隊的人來說，最加分的時候，不在於你寫得多快，而在於你能不能讓團隊持續交付優質功能。
如果自己都說不清楚「什麼樣的程式碼才算好」，在 code review 裡也很難幫到別人。

物件導向

什麼是物件導向程式設計？

物件導向（OO）不是把「封裝、繼承、多型」這三個詞死記硬背，而是先以「業務概念」與「行為邊界」為中心建模。

什麼是物件導向程式語言？

支援物件作為一級公民（有狀態且行為可組合）的語言都屬於 OO 語言。Java、C#、Python、TypeScript 是常見的例子。

什麼是物件導向分析與物件導向設計？

物件導向分析（OOA）關注「問題域中的核心物件是什麼」；
物件導向設計（OOD）關注「這些物件如何協作、如何隔離邊界、如何演進」。
