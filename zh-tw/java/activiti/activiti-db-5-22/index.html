Activiti 5.22 框架資料庫設計說明

按資料表分類整理 Activiti 5.22 工作流程引擎的資料庫結構、欄位與索引設計。

當時學習 Activiti 工作流程時，資料表很多，相關資訊也很分散，於是整理成一份結構化說明，方便日後查閱與排障。

由於專案環境主要使用 MySQL，以下範例均以 MySQL 為主。

結構設計

Activiti 使用到的資料表都有ACT_前綴，欄位名稱都有底線後綴，以避免關鍵字衝突。

ACT_RE_*:

‘RE’ 表示 repository（儲存），也就是 RepositoryService 介面所操作的資料表。帶有此前綴的資料表存放靜態資訊，例如流程定義、流程資源（圖片、規則等）。

ACT_RU_*:

‘RU’ 表示 runtime（執行時期），也就是 RuntimeService 所使用的執行時期資料表。這些資料表存放流程變數、使用者任務、作業（job）等執行時期資料。Activiti 只在流程實例執行期間保留執行時期資料，流程實例結束時就會刪除這些紀錄，因此這些執行時期資料表可以維持精簡、快速。

ACT_ID_*:

‘ID’ 表示 identity（組織），也就是 IdentityService 介面所操作的資料表。記錄流程中使用到的使用者與群組，並存放使用者、使用者群組等身分識別資訊。

ACT_HI_*:

‘HI’ 表示 history（歷史），也就是 HistoryService 所使用的歷史資料表。這些資料表存放與流程執行歷史相關的資料，例如已結束的流程實例、變數、任務等。

ACT_GE_*:

全域通用資料與設定（general），各種情況下都會用到。
