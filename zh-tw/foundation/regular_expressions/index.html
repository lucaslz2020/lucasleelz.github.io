正規表達式入門

從比對、處理文字的基本需求出發，系統理解正規表達式的核心概念與常用語法。

以前需要用正規表達式解決問題時，我往往先搜尋現成的寫法，改一改就湊合著用。
後來發現這樣做出來的結果常常「跑得通但不放心」，而且隔一段時間就忘，於是決定把基礎知識整理成一篇可重複使用的入門筆記，避免一再踩雷。

美國知名程式設計師 Jamie Zawinski 曾說過：

如果你有一個問題，你想到可以用正規表達式來解決，那麼你就有兩個問題了。

正規表達式是很難掌握、也很難善用的工具。

既然這麼難，使用的時候搜尋一下、解決問題就好了，為什麼還要學習呢？

如果不熟悉某項技術，遇到問題時根本不會想到可以用它來解決。

什麼是正規表達式

維基百科中的解釋：

正規表達式（英語：Regular Expression，常簡寫為 regex、regexp 或 RE），又稱正規表示式、正規表示法、規則表達式、常規表示法，是電腦科學的一個概念。正規表達式使用單一字串來描述並比對一組符合某個語法規則的字串。在許多文字編輯器中，正規表達式常用來搜尋、替換符合某個模式的文字。

簡單來說，正規表達式就是用來比對與處理文字的字串。

為什麼要使用正規表達式

工作時經常會用到正規表達式，例如檔案格式比對。

如何學習正規表達式？

每次都是搜尋一下、搞定就結束，日積月累反而可能浪費更多時間，而且容易忘記。

每天學一個小時、連續一週，總時間反而更短，也不容易忘記。

需求拆解

拿到需求後，可以拆成幾個子需求，並確認彼此是否獨立。

例如網址：

什麼是 URL

“protocol + domain name + port + path to the file + parameters + anchor”

Email：

username + @ + domain name

這也是我們日常軟體工程最基本的思路。

分析各個子需求

每個子需求可能涉及多個字元（字元組）、多個字串（分支），以及出現的次數（量詞）。

語言規則

查閱語法手冊，依照對應語言的規則寫下來就可以了。

TDD

使用 TDD 驗證表達式是否正確。一次不一定寫得對，先從最簡單的開始。

紅色表示測試失敗。

綠色表示測試通過。

測試通過後可以進行重構，並再次確保測試通過。

如何使用正規表達式？

保持克制。

想用一個表達式一口氣解決所有問題，但沒人看得懂，就失去可維護性，基本上只能重寫。

  1. 能用字串處理的，就使用字串。

  2. 一定要寫註解。

  3. 能用多個簡單的正規表達式解決的，就不要強求寫成一個複雜的正規表達式。

字元

比對文字

"I love JavaScript!".match(/love/);

比對多個結果

大多數正規表達式引擎預設只回傳第一個比對結果。

在 JavaScript 中使用 g（global，全域）旗標，會回傳所有比對結果的陣列。

"I love love love JavaScript!".match(/love/g);

不分大小寫的比對

預設情況下，正規表達式是區分大小寫的。JavaScript 使用 i 旗標強制執行不區分大小寫的比對。

"I love Love love JavaScript!".match(/love/gi);

比對任意字元

. 可以比對任意單一字元，包含字母、數字。

如果要比對真正的點，需要轉義成 \.。

"Z".match(/./); // [ 'Z', index: 0, input: 'Z', groups: undefined ]

比對特殊字元

點（.）在正規表達式中有特殊含義。如果真的需要比對點，就必須使用反斜線（\）進行轉義。

"test.js".match(/\.js/);

一組字元

比對一組字元

[] 本身不比對任何字元，只負責定義一個字元集合。字元集合代表「或（OR）」，而不是「和（AND）」。

[0123456789] 比對任何數字

"Mop top".match(/[tm]op/gi);

字元區間

指定一組字元，必須符合其中一個。

正規表達式經常使用字元區間（0~9、a-z 等）。為了簡化寫法，用 - 連字號來定義字元區間。

  1. - 只有在 [] 內才是元字元，在字元集合以外就只是一般的字元 -。
  2. 尾字元一定要大於首字元（例如 [9-1] 無效）。

[A-Z] 比對所有的大寫字母

[a-z] 比對所有的小寫字母

[0-9] 比對任何數字

[A-Za-z0-9] 比對字母與數字

[0-9A-Fa-f] 比對十六進位顏色

"test a string range".match(/[a-z]/g);

排除

使用 ^ 符號，排除字元集合中列出的字元。

[^0-9]：比對不是數字的字元

"No numbers here?".match(/[^0-9]/g);

元字元

它們有特殊含義，代表的不是字元本身。

比對空白元字元

不同作業系統使用的換行與回車方式不同，常見的是 \r\n。

元字元說明
[\b]回退（並刪除）一個字元（Backspace 鍵）
\f換頁符
\n換行符
\r回車符
\t製表符
\v垂直製表符

比對空白字元

元字元說明
\s=[\f\n\r\t\v]任何一個空白字元
\S=[^\f\n\r\t\v]任何一個非空白字元

\s 來自 space。

包含空格、製表符 \t、\v、\n、\f、\r。不包含回退。

\s 不包含 [\b]，\S 也沒有排除 [\b]。

比對數字

\d 來自 digit。

元字元說明
\d = [0-9]任何一個數字字元
\D = [^0-9]任何一個非數字字元
"123-123123-12312".match(/\d/g); // 数字
"123-123123-12312".match(/\D/g); // 非数字

比對字母、數字與底線

元字元說明
\w = [a-zA-Z0-9_]任何一個英數字或底線字元 _
\W = [^a-zA-Z0-9_]任何非英數字或底線的字元 _

\w 來自 word。

進位數值

\x 表示十六進位，\x0A 即字元 10

\0 表示八進位，\011 即字元 9

重複比對

比對一個或多個字元

+ = {1,}

"123-123123-12312".match(/\d+/g); //  [ '123', '123123', '12312' ]
"123-123123-12312".match(/\D+/g); //  [ '-', '-' ]

比對零個或多個字元

* = {0,1}

"100 10 1".match(/\d0*/g); // 100 10 1
"100 10 1".match(/\d0+/g); // 100 10

比對零個或一個字元

? = {0, 1}

這個符號可有可無，有點像可選運算子？

"Should I write color or colour?".match(/colou?r/g); //  [ 'color', 'colour' ]

比對指定的重複次數

\d{5} 表示 5 位數字。只能比對到 5 位數字；如果第六位還是數字，就比對不到。

"test 12345 test".match(/\d{5}/g); // 12345

比對重複次數區間

{m, n}

\d{2,4} 比對 2 到 4 次

"Today is 5 22, 2022".match(/\d{2,4}/g); // 22 2022

比對至少重複次數

{n,}

至少比對 4 次。

"Today is 5 22, 2022".match(/\d{4,}/g); // 2022

位置比對

單字邊界

使用 \b 表示，也就是單字與空格之間的位置。

正規表達式的「比對」有兩種概念：一種比對字元，一種比對位置。\b 就是比對位置。

"lucas lucas1 lucaslz".match(/\blucas\b/); // lucas

\B 不是單字邊界（有空格就是單字邊界，就比對不上了）。

"lucas lucas1 lucaslz".match(/\Blucas\B/); // null
"lucaslucas1lucaslz".match(/\Blucas\B/g); // lucas lucas  匹配第二个与第三个lucas

字串邊界

^ 表示字串開始；$ 表示字串結束。

"1本书，2本书".match(/^\d+/g); // 1
"1book,2book".match(/\w+$/g); // 2book
"1book,2book".match(/\w+$/g); // 2book
"1book，2book".match(/^\d\w+$/g); // null

多行模式

JavaScript 使用 /m 旗標表示多行模式。

它會影響 ^ 和 $ 的行為。

`
第1本书正则
第2本书JavaScript
第3本书HTML
`.match(/\d+/gm); // 1,2,3
`
1book
2book
`.match(/^\d\w+$/gm); // '1book', '2book'

子表達式

用來定義字元或表達式的集合。

() 定義一個子表達式。

用子表達式分組

沒有括號時，o 重複一次或多次。

"Googoogoo".match(/go+/gi); // 'Goo', 'goo', 'goo'

有括號時，將 go 視為整體重複一次或多次。

"Googoogoo".match(/(go)+/gi); //  'Go', 'go', 'go'

子表達式巢狀

這樣層層嵌套，可讀性很差。

/^(((\d{1,2})|(1\d{2})|(2[0-4]\d)|(25[0-5]))\.){3}((\d{1,2})|(1\d{2})|(2[0-4]\d)|(25[0-5]))$/;

或運算子

使用 | 表示，相當於條件選擇。

"19902021".match(/(19|20)/g); // 19 20

反向引用

在正規表達式內部被引用的子表達式，就稱為反向引用。

可以把反向引用想像成變數。

反向引用比對

"This is a test test text.".match(/\s+(\w+)\s+\1/g); // ' test test'

替換操作

JavaScript 在替換中使用 $。

const p = 'hello test@lucaslz.com';
const regex = /\w+[\w\.]*@[\w\,]+\.\w+)/;
p.replace(regex, '<a href="mailto:$1">$1</a>')

// result
hello <a href="mailto:test@lucaslz.com">test@lucaslz.com</a>

環視

有些時候需要用前後字元來確定文字比對的位置，但又不希望它們出現在最終結果中。

也叫做零寬斷言。

向前環視

(?=)

為了只比對後面有「日」的數字，需要使用向前環視。

"2022年5月29日".match(/\d+(?=日)/g); // 29

否定向前環視

(?!)

為了比對除了後面接「日」以外的數字。

"2022年5月29日".match(/\d+(?!日)/g); // '2022', '5', '2'  // 2后面也没有跟着日，所以会匹配上
"2022年5月29日".match(/\d+(?![\d+日])/g); //'2022', '5'

向後環視

(?<=)

比對收據上的金額，但不包含幣別符號。

"2022年5月29日订单金额￥12".match(/(?<=￥)\d+/g); // 12

否定向後環視

(?<!)

比對除了訂單金額以外的數字。

"2022年5月29日订单金额￥12".match(/(?!=￥)\d+/g); // '2022', '5', '29', '12'

貪婪比對

正規表達式預設執行貪婪比對，盡可能比對最多的字元，多多益善。

"ber beer beeer beeeer".match(/.*r/); // ber beer beeer beeeer

懶惰比對

盡可能比對最少的字元，第一個比對上就停止。

"ber beer beeer beeeer".match(/.*?r/); // ber
