Getting Started with Regular Expressions

Learn the core concepts and common syntax of regular expressions, beginning with the basic need to match and process text.

May 4, 2022 10 min read
#Regular Expression

When I needed to solve a problem with regex, I used to search for an answer, tweak it, and make do.
It usually ran fine, but I was never fully comfortable with it — and after a while I’d forget it all anyway. So I put the fundamentals together as a reusable introductory note, to stop repeating the same mistakes.

Jamie Zawinski, a well-known American programmer, once said:

Some people, when confronted with a problem, think “I know, I’ll use regular expressions.” Now they have two problems.

Regular expressions are notoriously hard to master and use well.

If they’re that hard, why not just search when you need them and move on? Why bother learning at all?

If you’re not familiar with a technique, it won’t even cross your mind to use it when a problem comes up.

What Is a Regular Expression

From Wikipedia:

A regular expression (English: Regular Expression, often shortened to regex, regexp, or RE), also called a rational expression, is a concept in computer science. A regular expression uses a single string to describe and match strings that follow a given syntax rule. In many text editors, regular expressions are commonly used to find and replace text that matches a pattern.

In short, a regex is a string used to match and process text.

Why Use Regular Expressions

You’ll run into regular expressions all the time at work — for example, matching file formats.

How to Learn Regular Expressions?

Looking things up each time and moving on once it works may feel efficient, but it adds up over time — and it’s easy to forget.

An hour a day for one week actually takes less total time, and it sticks much better.

Break Down the Requirement

When you receive a requirement, break it down into sub-requirements and check whether they’re independent of one another.

For example, a URL:

What is a URL

“protocol + domain name + port + path to the file + parameters + anchor”

An email address:

username + @ + domain name

This is also the most fundamental way of thinking in everyday software engineering.

Analyze Each Sub-Requirement

Each sub-requirement may involve multiple characters (character sets), multiple strings (alternation), and occurrence counts (quantifiers).

Language Rules

Consult the syntax reference and write the expression according to the rules of the language you’re using.

TDD

Use TDD to verify whether the expression is correct. You won’t necessarily get it right on the first try — start with the simplest case.

Red means the test fails.

Green means the test passes.

Once the test passes, you can refactor — then make sure it still passes.

How to Use Regular Expressions?

Exercise restraint.

A regex that tries to solve everything at once is unreadable to anyone else — it has no maintainability, and in practice the only option is to rewrite it.

  1. If string handling can do the job, use strings.

  2. Always write comments.

  3. If a few simple regexes can solve the problem, don’t force everything into one complex regex.

Characters

Matching Text

"I love JavaScript!".match(/love/);

Matching Multiple Results

By default, most regex engines return only the first match.

In JavaScript, the g (global) flag returns an array of all matches.

"I love love love JavaScript!".match(/love/g);

Case-Insensitive Matching

By default, regexes are case-sensitive. JavaScript’s i flag enforces case-insensitive matching.

"I love Love love JavaScript!".match(/love/gi);

Matching Any Character

. matches any single character — including letters and digits.

To match a literal dot, escape it with \..

"Z".match(/./); // [ 'Z', index: 0, input: 'Z', groups: undefined ]

Matching Special Characters

The dot (.) has special meaning in regex. If you really need to match a dot, escape it with a backslash (\).

"test.js".match(/\.js/);

A Set of Characters

Matching a Set of Characters

[] matches nothing by itself; it only defines a set of characters. A character set is an OR relationship, not an AND one.

[0123456789] matches any digit.

"Mop top".match(/[tm]op/gi);

Character Ranges

Specify a set of characters, any one of which must match.

Regexes frequently rely on character ranges (0–9, a–z, and so on). To keep things concise, ranges are defined with the - hyphen.

  1. - is only a metacharacter inside []; outside a character set, it’s an ordinary -.
  2. The ending character must be greater than the starting character (e.g. [9-1] is invalid).

[A-Z] matches all uppercase letters.

[a-z] matches all lowercase letters.

[0-9] matches any digit.

[A-Za-z0-9] matches letters and digits.

[0-9A-Fa-f] matches hex colors.

"test a string range".match(/[a-z]/g);

Exclusion

Use ^ inside a character set to exclude the characters it lists.

[^0-9]: matches any character that is not a digit

"No numbers here?".match(/[^0-9]/g);

Metacharacters

They carry special meaning and don’t represent the characters themselves.

Whitespace Metacharacters

Different operating systems use different line breaks and carriage returns; \r\n is the most common.

MetacharacterDescription
[\b]Backspace (deletes a character)
\fForm feed
\nLine feed
\rCarriage return
\tTab
\vVertical tab

Matching Whitespace Characters

MetacharacterDescription
\s=[\f\n\r\t\v]Any whitespace character
\S=[^\f\n\r\t\v]Any non-whitespace character

\s comes from space.

It covers spaces, tabs \t, \v, \n, \f, and \r. It does not include backspace.

\s doesn’t include [\b], and \S doesn’t exclude [\b] either.

Matching Digits

\d comes from digit.

MetacharacterDescription
\d = [0-9]Any digit character
\D = [^0-9]Any non-digit character
"123-123123-12312".match(/\d/g); // 数字
"123-123123-12312".match(/\D/g); // 非数字

Matching Letters, Digits, and Underscore

MetacharacterDescription
\w = [a-zA-Z0-9_]Any letter, digit, or underscore character _
\W = [^a-zA-Z0-9_]Any character that is not a letter, digit, or underscore _

\w comes from word.

Numeric Values in Different Bases

\x denotes hexadecimal — \x0A is character 10

\0 denotes octal — \011 is character 9

Repeated Matching

Matching One or More Characters

+ = {1,}

"123-123123-12312".match(/\d+/g); //  [ '123', '123123', '12312' ]
"123-123123-12312".match(/\D+/g); //  [ '-', '-' ]

Matching Zero or More Characters

* = {0,1}

"100 10 1".match(/\d0*/g); // 100 10 1
"100 10 1".match(/\d0+/g); // 100 10

Matching Zero or One Character

? = {0, 1}

The symbol is optional — a bit like an optional operator?

"Should I write color or colour?".match(/colou?r/g); //  [ 'color', 'colour' ]

Matching an Exact Number of Repetitions

\d{5} matches exactly five digits: if the sixth character is also a digit, it won’t match.

"test 12345 test".match(/\d{5}/g); // 12345

Matching a Range of Repetitions

{m, n}

\d{2,4} matches 2 to 4 times.

"Today is 5 22, 2022".match(/\d{2,4}/g); // 22 2022

Matching at Least n Repetitions

{n,}

Match at least 4 times.

"Today is 5 22, 2022".match(/\d{4,}/g); // 2022

Position Matching

Word Boundaries

\b denotes a word boundary — the position between a word and whitespace.

In regex, “match” has two senses: matching a character and matching a position. \b matches a position.

"lucas lucas1 lucaslz".match(/\blucas\b/); // lucas

\B is a non-word-boundary (if there’s whitespace, there’s a word boundary, so it won’t match).

"lucas lucas1 lucaslz".match(/\Blucas\B/); // null
"lucaslucas1lucaslz".match(/\Blucas\B/g); // lucas lucas  匹配第二个与第三个lucas

String Boundaries

^ marks the start of the string; $ marks the end of the string.

"1本书，2本书".match(/^\d+/g); // 1
"1book,2book".match(/\w+$/g); // 2book
"1book,2book".match(/\w+$/g); // 2book
"1book，2book".match(/^\d\w+$/g); // null

Multiline Mode

JavaScript’s /m flag enables multiline mode.

It affects the behavior of the ^ and $ anchors.

`
第1本书正则
第2本书JavaScript
第3本书HTML
`.match(/\d+/gm); // 1,2,3
`
1book
2book
`.match(/^\d\w+$/gm); // '1book', '2book'

Subexpressions

Used to define a group of characters or expressions.

() defines a subexpression.

Grouping with Subexpressions

Without parentheses, o repeats one or more times.

"Googoogoo".match(/go+/gi); // 'Goo', 'goo', 'goo'

With parentheses, go repeats as a whole one or more times.

"Googoogoo".match(/(go)+/gi); //  'Go', 'go', 'go'

Nested Subexpressions

Layer upon layer of nesting makes it very hard to read.

/^(((\d{1,2})|(1\d{2})|(2[0-4]\d)|(25[0-5]))\.){3}((\d{1,2})|(1\d{2})|(2[0-4]\d)|(25[0-5]))$/;

The Alternation Operator

| represents alternation — a choice between options.

"19902021".match(/(19|20)/g); // 19 20

Backreferences

A subexpression that’s referenced from inside the regex is called a backreference.

Think of a backreference as a variable.

Matching with Backreferences

"This is a test test text.".match(/\s+(\w+)\s+\1/g); // ' test test'

Replacement

JavaScript uses $ in replacements.

const p = 'hello test@lucaslz.com';
const regex = /\w+[\w\.]*@[\w\,]+\.\w+)/;
p.replace(regex, '<a href="mailto:$1">$1</a>')

// result
hello <a href="mailto:test@lucaslz.com">test@lucaslz.com</a>

Lookaround

Sometimes you need the characters before or after to determine where text matches, but you don’t want them in the final result.

This is also called a zero-width assertion.

Lookahead

(?=)

To match only digits followed by 日, use lookahead.

"2022年5月29日".match(/\d+(?=日)/g); // 29

Negative Lookahead

(?!)

To match digits other than those followed by 日.

"2022年5月29日".match(/\d+(?!日)/g); // '2022', '5', '2'  // 2后面也没有跟着日，所以会匹配上
"2022年5月29日".match(/\d+(?![\d+日])/g); //'2022', '5'

Lookbehind

(?<=)

Match the amount on the receipt without the currency symbol.

"2022年5月29日订单金额￥12".match(/(?<=￥)\d+/g); // 12

Negative Lookbehind

(?<!)

Match digits other than the order amount.

"2022年5月29日订单金额￥12".match(/(?!=￥)\d+/g); // '2022', '5', '29', '12'

Greedy Matching

Regexes are greedy by default: they match as many characters as possible — the more, the better.

"ber beer beeer beeeer".match(/.*r/); // ber beer beeer beeeer

Lazy Matching

Match as few characters as possible and stop at the first match.

"ber beer beeer beeeer".match(/.*?r/); // ber
