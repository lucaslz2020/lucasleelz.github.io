Three-Node Nacos Cluster on Kubernetes: From Service to StatefulSet

Set up a three-node Nacos cluster: database, Secret, Headless Service, Service, StatefulSet — authentication, anti-affinity, probes, and acceptance checks.

lucaslzAuthor
June 14, 2026 7 min read
#Kubernetes #Nacos #StatefulSet #Service #MySQL
{ }

This post does exactly one thing: set up a three-node Nacos cluster in a Kubernetes cluster that already has CNI, DNS, and dynamic storage.

Series navigation: Kubernetes Rebuild Migration Tutorial Series. After this post, move on to Service DNS governance and smooth upgrades.

All image versions, domains, passwords, and addresses in this post are placeholders. Before deploying to production, verify the environment variables and database schema against the target Nacos image — don’t just use latest.

Understand the final structure first

Nacos needs only three Pods, but it needs two Services:

  • nacos-headless has clusterIP: None, which gives StatefulSet Pods stable DNS so the three Nacos nodes can discover each other.
  • nacos-client is a regular ClusterIP Service. Applications connect only to it and never care about a specific Pod IP.
  • Configuration and service registration data live in the external MySQL, so nothing is lost when Pods are recreated.

The Headless Service is not an additional Nacos instance, and business clients don’t need to use it directly.

Prerequisites

First confirm the cluster’s basic capabilities:

kubectl get nodes
kubectl get storageclass
kubectl -n kube-system get deployment coredns
kubectl run dns-smoke --image=<approved-busybox-image> --restart=Never \
  --command -- nslookup kubernetes.default.svc.cluster.local
kubectl logs dns-smoke
kubectl delete pod dns-smoke

Requirements:

  • At least three schedulable worker nodes.
  • The default StorageClass can dynamically create PVCs, or static PVs are already in place.
  • The external MySQL is highly available and has independent backups.
  • The Nacos image is synced to the internal registry with a pinned digest.
  • Network and DNS from nodes to MySQL are verified.

Step 1: Prepare the namespace and database

Create a dedicated namespace:

kubectl create namespace nacos-system

Get the mysql-schema.sql for the matching database from the target Nacos distribution, run it against a test database first, then have the database administrator apply it to the production database. Don’t copy an SQL file of unknown version from the old blog.

After running it, at least confirm the core tables exist:

SHOW TABLES;
SELECT COUNT(*) FROM config_info;
SELECT COUNT(*) FROM tenant_info;

Grant the database account only the permissions the Nacos schema needs. Don’t use MySQL root in application Pods.

Step 2: Generate authentication material and the Secret

The Nacos auth token is created from a random value of at least 32 bytes and then Base64-encoded. The following commands store the results only in the current shell’s variables:

NACOS_RAW_TOKEN="$(openssl rand -hex 32)"
NACOS_AUTH_TOKEN="$(printf '%s' "$NACOS_RAW_TOKEN" | base64)"

kubectl -n nacos-system create secret generic nacos-secret \
  --from-literal=mysql-host='<mysql-host>' \
  --from-literal=mysql-port='<mysql-port>' \
  --from-literal=mysql-database='<mysql-database>' \
  --from-literal=mysql-username='<mysql-username>' \
  --from-literal=mysql-password='<mysql-password>' \
  --from-literal=auth-token="$NACOS_AUTH_TOKEN" \
  --from-literal=identity-key='serverIdentity' \
  --from-literal=identity-value='<random-identity-value>'

unset NACOS_RAW_TOKEN NACOS_AUTH_TOKEN

The Secret must not be committed to Git. What goes into the repository is an ExternalSecret or SealedSecret template, or setup instructions without values.

Step 3: Create the two Services

Save as 00-services.yaml:

apiVersion: v1
kind: Service
metadata:
  name: nacos-headless
  namespace: nacos-system
spec:
  clusterIP: None
  publishNotReadyAddresses: true
  selector:
    app.kubernetes.io/name: nacos
  ports:
    - name: http
      port: 8848
    - name: grpc-client
      port: 9848
    - name: grpc-server
      port: 9849
    - name: raft
      port: 7848
---
apiVersion: v1
kind: Service
metadata:
  name: nacos-client
  namespace: nacos-system
spec:
  selector:
    app.kubernetes.io/name: nacos
  ports:
    - name: http
      port: 8848
      targetPort: http
    - name: grpc-client
      port: 9848
      targetPort: grpc-client
    - name: console
      port: 8080
      targetPort: console

The application address should be:

nacos-client.nacos-system.svc.cluster.local:8848

Create and check:

kubectl apply -f 00-services.yaml
kubectl -n nacos-system get service

nacos-headless should show ClusterIP None, and nacos-client should get a regular ClusterIP.

Step 4: Create the three-node StatefulSet

Save as 01-statefulset.yaml. Below is the core structure. Recheck the environment variable names against your pinned target image:

apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: nacos
  namespace: nacos-system
spec:
  serviceName: nacos-headless
  replicas: 3
  podManagementPolicy: Parallel
  updateStrategy:
    type: RollingUpdate
  selector:
    matchLabels:
      app.kubernetes.io/name: nacos
  template:
    metadata:
      labels:
        app.kubernetes.io/name: nacos
    spec:
      terminationGracePeriodSeconds: 60
      affinity:
        podAntiAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            - labelSelector:
                matchLabels:
                  app.kubernetes.io/name: nacos
              topologyKey: kubernetes.io/hostname
      containers:
        - name: nacos
          image: <image-registry>/nacos-server:<approved-version>@sha256:<digest>
          imagePullPolicy: IfNotPresent
          ports:
            - { name: http, containerPort: 8848 }
            - { name: grpc-client, containerPort: 9848 }
            - { name: grpc-server, containerPort: 9849 }
            - { name: raft, containerPort: 7848 }
            - { name: console, containerPort: 8080 }
          env:
            - { name: MODE, value: cluster }
            - { name: PREFER_HOST_MODE, value: hostname }
            - {
                name: NACOS_SERVERS,
                value: "nacos-0.nacos-headless.nacos-system.svc.cluster.local:8848 nacos-1.nacos-headless.nacos-system.svc.cluster.local:8848 nacos-2.nacos-headless.nacos-system.svc.cluster.local:8848",
              }
            - { name: SPRING_DATASOURCE_PLATFORM, value: mysql }
            - name: MYSQL_SERVICE_HOST
              valueFrom:
                { secretKeyRef: { name: nacos-secret, key: mysql-host } }
            - name: MYSQL_SERVICE_PORT
              valueFrom:
                { secretKeyRef: { name: nacos-secret, key: mysql-port } }
            - name: MYSQL_SERVICE_DB_NAME
              valueFrom:
                { secretKeyRef: { name: nacos-secret, key: mysql-database } }
            - name: MYSQL_SERVICE_USER
              valueFrom:
                { secretKeyRef: { name: nacos-secret, key: mysql-username } }
            - name: MYSQL_SERVICE_PASSWORD
              valueFrom:
                { secretKeyRef: { name: nacos-secret, key: mysql-password } }
            - { name: NACOS_AUTH_ENABLE, value: "true" }
            - name: NACOS_AUTH_TOKEN
              valueFrom:
                { secretKeyRef: { name: nacos-secret, key: auth-token } }
            - name: NACOS_AUTH_IDENTITY_KEY
              valueFrom:
                { secretKeyRef: { name: nacos-secret, key: identity-key } }
            - name: NACOS_AUTH_IDENTITY_VALUE
              valueFrom:
                { secretKeyRef: { name: nacos-secret, key: identity-value } }
          startupProbe:
            httpGet: { path: /nacos/v1/console/health/started, port: http }
            periodSeconds: 10
            timeoutSeconds: 5
            failureThreshold: 30
          readinessProbe:
            httpGet: { path: /nacos/v1/console/health/readiness, port: http }
            periodSeconds: 10
            timeoutSeconds: 5
            failureThreshold: 6
          livenessProbe:
            httpGet: { path: /nacos/v1/console/health/liveness, port: http }
            periodSeconds: 20
            timeoutSeconds: 5
            failureThreshold: 6
          resources:
            requests: { cpu: "1", memory: 2Gi }
            limits: { cpu: "2", memory: 4Gi }

Probe paths may vary by target version. Verify them with curl in the test environment using the target image before putting them in the production manifest.

Create the StatefulSet:

kubectl apply --server-side --dry-run=server -f 01-statefulset.yaml
kubectl apply -f 01-statefulset.yaml
kubectl -n nacos-system rollout status statefulset/nacos --timeout=15m
kubectl -n nacos-system get pods -o wide

The three Pods should be spread across three different nodes. If a Pod is Pending, check the events first:

kubectl -n nacos-system describe pod nacos-2

If the cluster has only two suitable nodes, required anti-affinity will block the third Pod from scheduling. This is a capacity planning problem and should not be masked by removing the anti-affinity.

Step 5: Verify node discovery, the database, and the Service

Check the logs one by one:

for pod in nacos-0 nacos-1 nacos-2; do
  echo "===== ${pod} ====="
  kubectl -n nacos-system logs "$pod" --tail=100
done

Check DNS:

kubectl -n nacos-system exec nacos-0 -- \
  getent hosts nacos-1.nacos-headless.nacos-system.svc.cluster.local

Check Service endpoints:

kubectl -n nacos-system get endpointslice \
  -l kubernetes.io/service-name=nacos-client -o wide

The EndpointSlice should have three Ready addresses. Finally, access the client Service from a temporary Pod:

kubectl -n nacos-system run nacos-smoke --rm -it --restart=Never \
  --image=<approved-curl-image> -- \
  curl -fsS http://nacos-client:8848/nacos/v1/console/health/readiness

Step 6: Connect the first application

Start with a non-core application; don’t change all namespaces at once:

spring.cloud.nacos.server-addr=nacos-client.nacos-system.svc.cluster.local:8848
spring.cloud.nacos.username=${NACOS_USERNAME}
spring.cloud.nacos.password=${NACOS_PASSWORD}

After deploying, run both checks:

kubectl -n <app-namespace> rollout status deployment/<app> --timeout=10m
kubectl -n <app-namespace> logs deployment/<app> --since=10m \
  | grep -Ei 'nacos|register|error|exception'

Then check the registered instances from the Nacos console or API — rather than just verifying that the application Pod is Running.

Definition of Done

The Nacos cluster is complete only when all of the following hold:

  • The three Nacos Pods are on three different nodes.
  • Each Pod can resolve the Headless DNS of the other two Pods.
  • nacos-client has three Ready endpoints.
  • Config publishing, reading, and historical versions all work normally.
  • A test application can register, discover, and call another service.
  • After deleting any Nacos Pod, applications can still read config and discover services.
  • Both MySQL and the Nacos configuration have independent backup and restore procedures.

The official quick start explicitly notes that its default manifest is only suitable for testing; production deployments should enable authentication, use a reliable database and persistence solution, and run in an isolated internal network. See Nacos Kubernetes Quick Start and Nacos Cluster Mode Deployment.
