CSS-in-JS

Understand the motivation behind CSS-in-JS, how it works, and when to use it — starting from the principle of separation of concerns.

Traditional Development

In typical web development, CSS, HTML, and JavaScript are kept separate.

HTML handles the structure of a web page.

CSS handles the styling (visual effects) of every element on the page.

JavaScript handles the interactions (logic) between the page and the user.

This design principle — dividing a computer program into separate parts — is called the separation of concerns (SoC). HTML, CSS, and JavaScript are a classic application of this principle.

What Is CSS-in-JS

CSS-in-JS is a styling technique that writes CSS with JavaScript — in other words, it integrates CSS into JavaScript. This can feel counterintuitive.

When this JavaScript is executed, it generates CSS (usually as a <style> element) and attaches it to the DOM.

Why CSS-in-JS?

In traditional development, CSS files are usually linked directly in HTML. Styles lack scoping isolation, so they can easily override one another.

Modern development is increasingly component-based, and styles are expected to apply within component boundaries. CSS-in-JS does exactly that — it keeps styles close to where they are used and prevents them from leaking.

Solving the Scoping Problem

CSS-in-JS uses JavaScript scoping to simulate CSS scoping, giving CSS an isolated scope of its own. Styles stay inside the component instead of leaking out and conflicting with others — solving the problem of CSS having no scope.

Increasing Component Independence and Portability

When moving a component, you might forget its style file — or not even know where it is. With CSS-in-JS, a component is a single self-contained file — just move it and it works out of the box, making it easy to build loosely coupled applications.

Reusability

Write once, run anywhere: components can be reused not only within the same application, but also in other applications built with the same framework.

Dynamism

CSS isn’t dynamic — you can’t conditionally apply styles to an element. With CSS-in-JS, you can use JavaScript’s dynamic capabilities to apply styles conditionally, so even complex logic can drive style rules. That makes it an ideal solution for complex, dynamic UIs.

On-Demand Imports

As applications grow, components get larger, so on-demand imports become necessary. Combined with tree-shaking, CSS-in-JS makes this much easier to achieve.

In short, CSS-in-JS addresses CSS’s limitations, such as its lack of dynamism, scoping, and portability.

Pros and Cons

Summary

It is particularly well suited to component libraries.

CSS-in-JS is just a pattern; it requires framework support.

Common frameworks include:

  • Emotion
  • Styled Components
  • JSS
