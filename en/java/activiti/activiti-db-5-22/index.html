Activiti 5.22 Database Design Guide

A table-by-table breakdown of the Activiti 5.22 workflow engine's database structure, fields, and index design.

When I was learning the Activiti workflow, the many tables and their scattered meanings were hard to keep straight, so I organized them into a structured reference for later lookup and troubleshooting.

Since the project environment mainly used MySQL, the examples below are based on MySQL.

Schema Design

All tables used by Activiti have the ACT_ prefix, and all column names end with an underscore suffix to prevent keyword conflicts.

ACT_RE_*:

‘RE’ stands for repository (storage) — the tables operated on by the RepositoryService interface. Tables with this prefix contain static information, such as process definitions and process resources (images, rules, etc.).

ACT_RU_*:

‘RU’ stands for runtime — the runtime tables used by RuntimeService. These tables store runtime data such as process variables, user tasks, and jobs. Activiti only stores runtime data while an instance is executing and deletes these records when the process instance ends. This keeps the runtime tables small and fast.

ACT_ID_*:

‘ID’ stands for identity (organization) — the tables operated on by the IdentityService interface. They record the users and groups used in processes, holding identity information such as users and user groups.

ACT_HI_*:

‘HI’ stands for history — the history tables used by HistoryService. These tables contain data related to process execution history, such as completed process instances, variables, tasks, and so on.

ACT_GE_*:

Global general-purpose data and settings (general) — data needed in various situations.

ACT_GE_BYTEARRAY (Binary Data Table)

Stores process definition images, XML, and Serializable variables — that is, all binary data. Note that when deploying from the classpath, you should not deploy hidden files such as SVN files or other files unrelated to the process; doing so can cause errors and may even prevent process definitions from being deleted.

ACT_RE_PROCDEF (Process Definition Table)

The business process definition table. It has a many-to-one relationship with the ACT_RE_DEPLOYMENT table: a deployed bar package may contain multiple process definition files, and each file has a record in the ACT_RE_PROCDEF table. Each process definition corresponds to a resource file and a PNG image file in the ACT_GE_BYTEARRAY table. The association with ACT_GE_BYTEARRAY is made programmatically using ACT_GE_BYTEARRAY.NAME_ and ACT_RE_PROCDEF.NAME_; it is not reflected in the database schema.
