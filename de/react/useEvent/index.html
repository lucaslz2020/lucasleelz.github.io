useEvent: Stabile Funktionsreferenzen für Event-Handler

Ausgehend vom Closure-Problem und wechselnden Funktionsreferenzen verstehen, welche React-Hooks-Probleme das useEvent-RFC lösen will.

lucaslzAutor
15. Mai 2022 8 Min. Lesezeit
#React #React Hooks
Aktualitätshinweis Zuletzt verifiziert am 15. Mai 2022. Die relevanten Versionen können sich seither geändert haben; prüfen Sie vor der Umsetzung die aktuellen offiziellen Dokumente.
{ }

Das React-Team hat ein useEvent-RFC veröffentlicht.

Es ist ein Event-Handler-Hook, der immer stabile Funktionsreferenzen liefert und damit das Closure-Problem in Event-Callbacks löst.

Er beseitigt einige Schwachstellen von useCallback und reduziert die kognitive Last.

Das RFC steckt noch in der frühen Diskussionsphase des React-Teams. Bevor du es einsetzt, solltest du es anhand deiner aktuellen React-Version und der Release Notes bewerten.

Motivation

Im onClick-Handler soll der aktuell eingegebene text gelesen werden:

function Chat() {
  const [text, setText] = useState("");

  // 永远是新的函数引用
  const onClick = () => {
    sendMessage(text);
  };

  return <SendButton onClick={onClick} />;
}

Zur Leistungsoptimierung wird SendButton üblicherweise in React.memo gewrappt. Damit das greift und unnötiges Rendering ausbleibt, müssen die props einen flachen Vergleich bestehen. onClick erzeugt aber bei jedem Render eine neue Funktionsreferenz und macht die Optimierung damit zunichte.

export interface SendButtonProps {
  children: ReactNode;
  onClick: () => void;
}

const SendButton = ({ children, onClick }: SendButtonProps) => {
  return <button onClick={onClick}>{children}</button>;
};

export default memo(SendButton);

Üblicherweise packt man onClick in useCallback, um die Funktionsreferenz zu erhalten.

const onClick = useCallback(() => {
  sendMessage(text);
}, []);

Wer am Anfang steht, vergisst schnell die Dependencies – dann bekommt sendMessage nie den aktuellen Wert. (Closure-Problem)

const onClick = useCallback(() => {
  sendMessage(text);
}, [text]);

Ändert sich die Dependency text, gibt useCallback eine neue onClick-Referenz zurück, sodass sendMessage den aktuellen Wert bekommt.

Das Problem: Sobald sich text ändert, ändert sich auch die onClick-Referenz – und useCallback verliert seinen Cache-Effekt.

useEventCallback

Die offizielle Doku hat dafür bereits eine Lösung: Wie liest man einen sich häufig ändernden Wert aus useCallback?.

Will man die Funktionsreferenz behalten und trotzdem im Inneren den aktuellen Wert lesen, bietet sich ein ref als Instanzvariable an – es löst kein Rendering aus.

const [text, setText] = useState("");
const textRef = useRef<string>();

useEffect(() => {
  textRef.current = text; // 每次都把最新的text写入ref中
});

const sendMessage = (text?: string) => {
  console.log("text", text);
};

const onClick = useCallback(() => {
  sendMessage(textRef.current); // 从ref中获取最新值
}, [textRef]); // 这个并不是重新生成函数引用。

return (
  <>
    <input value={text} onChange={(event) => setText(event.target.value)} />
    <SendButton onClick={onClick}>按钮Ref</SendButton>
  </>
);

Dieses Muster ist umständlich – jedes Mal steht derselbe Boilerplate an. Man kann es in einen Custom Hook auslagern:

const [text, updateText] = useState("");
// 即使 `text` 变了也会被记住:
const handleSubmit = useEventCallback(() => {
  alert(text);
}, [text]);

return (
  <>
    <input value={text} onChange={(e) => updateText(e.target.value)} />
    <SendButton onClick={handleSubmit}>useEventCallback按钮</SendButton>
  </>
);

Die Implementierung des useEventCallback-Hooks:

type Fn = () => void;

export function useEventCallback(fn: Fn, dependencies: DependencyList) {
  const ref = useRef<Fn>(() => {
    throw new Error("Cannot call an event handler while rendering.");
  });

  // 每次渲染就把最新的函数存入到ref中
  useEffect(() => {
    ref.current = fn;
  }, [fn, ...dependencies]);

  // 函数引用永远不会发生变化。但是可以从ref中获取最新的值（函数）
  return useCallback(() => {
    const fn = ref.current;
    return fn();
  }, [ref]);
}

Die offizielle Doku rät ausdrücklich von diesem Muster ab und empfiehlt, dispatch über context weiterzureichen.

Inzwischen scheint das React-Team aber nachgegeben zu haben.

useEvent

useEvent kommt ohne Dependency-Array aus, gibt immer dieselbe Funktionsreferenz zurück und liefert trotzdem den aktuellen text.

const [text, updateText] = useState("");
// 即便 text 变了也会被记住:
const handleSubmit = useEvent(() => {
  alert(text);
});

return (
  <>
    <input value={text} onChange={(e) => updateText(e.target.value)} />
    <SendButton onClick={handleSubmit}>useEvent按钮</SendButton>
  </>
);

Eine Beispielimplementierung von useEvent:

export function useEvent(handler: Fn) {
  const handlerRef = useRef<Fn | null>(null);

  // 视图渲染后更新handlerRef.current, 函数触发时始终是最新的引用。
  useLayoutEffect(() => {
    handlerRef.current = handler;
  });

  // 没有依赖项，每次render时函数的引用一致
  return useCallback((...args) => {
    const fn = handlerRef.current;
    return fn?.(...args);
  }, []);
}

Szenarien

useEffect soll sich bei wechselnder Event-Funktion nicht erneut ausführen

Chat verbindet sich mit dem ausgewählten Raum, loggt Beitritte und Nachrichten und entscheidet anhand von muted, ob ein Ton abgespielt wird.

export const Chat = ({ selectedRoom }: ChatProps) => {
  const [muted, setMuted] = useState();
  const theme = useContext(ThemeContext);

  useEffect(() => {
    const socket = createSocket("/chat/" + selectedRoom);
    socket.on("connected", async () => {
      await checkedConnection(selectedRoom);
      console.log(theme, "Connected to" + selectedRoom);
    });
    socket.on("message", (message) => {
      console.log(theme, "New message" + message);
      if (!muted) {
        playSound();
      }
    });
    socket.connect();
    return () => socket.close();
  }, [selectedRoom, theme, muted]);
};

Ändern sich theme oder muted, wird der socket zerstört, neu erstellt und wieder verbunden. Der Grund: useEffect nutzt beide Werte, also müssen sie in den Dependencies stehen.

Wer den Linter ignoriert oder theme und muted aus den Dependencies entfernt, bekommt in connected und message nie die aktuellen Werte. Closure-Problem

Warum darf man den Linter nicht deaktivieren?

Das kann größere Probleme nach sich ziehen – etwa wenn useEffect(() => {}, []) in React 18 mehrfach ausgeführt wird.

Mit useEvent löst man das so:

export const Chat = ({ selectedRoom }: ChatProps) => {
  const [muted, setMuted] = useState();
  const theme = useContext(ThemeContext);

  const onConnected = useEvent(async (selectedRoom) => {
    await checkedConnection(selectedRoom);
    console.log(theme, "Connected to" + selectedRoom);
  });

  const onMessage = useEvent((message: string) => {
    console.log(theme, "New message" + message);
    if (!muted) {
      playSound();
    }
  });

  useEffect(() => {
    const socket = createSocket("/chat/" + selectedRoom);
    socket.on("connected", () => onConnected(selectedRoom));
    socket.on("message", onMessage);
    socket.connect();
    return () => socket.close();
  }, [selectedRoom]); // 只有当房间号改变时才会销毁socket。重新创建socket并连接
};

Parameter an das Event übergeben

In onConnected und onMessage stehen die aktuellen Werte von theme und muted zur Verfügung.

selectedRoom kann jedoch veraltet sein und muss deshalb als Parameter an onConnected übergeben werden.

Kapselung in einem Custom Hook

export const useRoom = (room: string, events: {}) => {
  const onConnected = useEvent(events.onConnected);
  const onMessage = useEvent(events.onMessage);

  useEffect(() => {
    const socket = createSocket(room);
    socket.on("connected", onConnected);
    socket.on("message", onMessage);
    socket.connect();
    return () => socket.close();
  }, [room]); // 只有当房间号改变时才会销毁socket。重新创建socket并连接
};

Die übergebenen Event-Callbacks werden in useEvent gepackt: Die Funktionsreferenzen bleiben garantiert stabil, und useEffect wird nie erneut ausgelöst.

const [muted, setMuted] = useState();
const theme = useContext(ThemeContext);
const onConnected = useEvent(async (connectedRoom) => {
  await checkedConnection(selectedRoom);
  console.log(theme, "Connected to" + selectedRoom);
});

const onMessage = useEvent((message: string) => {
  console.log(theme, "New message" + message);
  if (!muted) {
    playSound();
  }
});

useRoom(selectedRoom, { onConnected, onMessage });

Event-Tracking

Das Tracking hängt von url und name ab. Nur wenn sich url ändert, soll neu getrackt werden; eine Änderung an name darf das Tracking nicht erneut auslösen.

export const Tracking = ({ url, name }: TrackingProps) => {
  useEffect(() => {
    logAnalytics("visit_page", url, name);
  }, [url, name]);
};

Bisheriger Ansatz

const urlRef = useRef<string>();
useEffect(() => {
  if (urlRef.current === url) {
    return;
  }
  logAnalytics("visit_page", url, name);
  urlRef.current = url; // 保证urlRef引用最新的url值。
}, [url, name]);

Mit useEvent

Achtung: url muss als Parameter übergeben werden:

const onVisit = useEvent((url: string) => {
  logAnalytics("visit_page", url, name);
});
useEffect(() => {
  onVisit(url);
}, [url]);

Timer

Bei einem E-Mail-System soll der Mailinhalt regelmäßig als Entwurf gespeichert werden.

useEffect(() => {
  const id = setInterval(() => {
    saveDraft(content);
  }, 1000);
  return () => clearInterval(id);
}, [content]);

Jede Änderung an content startet den Timer neu.

Ohne die Dependency bekommt saveDraft den aktuellen content nicht mehr.

Bisheriger Ansatz

const [content, setContent] = useState();
const handleSaveDraftRef = useRef<() => void>();

const handleSaveDraft = () => {
  saveDraft(content);
};

useEffect(() => {
  handleSaveDraftRef.current = handleSaveDraft;
});

useEffect(() => {
  const id = setInterval(() => {
    handleSaveDraftRef.current?.();
  }, 1000);
  return () => clearInterval(id);
}, []);

Das ist ziemlich umständlich.

Mit useEvent

const [content, setContent] = useState();

const handleSaveDraft = useEvent(() => {
  saveDraft(content);
});

useEffect(() => {
  const id = setInterval(handleSaveDraft, 1000);
  return () => clearInterval(id);
}, []);
