Emotion

Eine systematische Übersicht über Emotions Konfiguration, Styling-Ansätze, Theming und die praktische Verwendung mit React.

Emotion ist eine Bibliothek zum Schreiben von CSS-Styles mit JavaScript – ideal, wenn du Theming und dynamische Styles zur Laufzeit brauchst.

Es gibt zwei gängige Einsatzweisen: den framework-unabhängigen Modus und die komponentenbasierte Variante für React.

Offizielle Website

GitHub

Konfiguration der css-Eigenschaft

In Emotion kannst du Elementen eine css-Eigenschaft geben; standardmäßig weiß das Framework aber nicht, wie es sie auflösen soll. Deshalb ist eine entsprechende Konfiguration nötig.

TypeScript-Konfiguration für Emotion

"jsxImportSource": "@emotion/react"

Andernfalls kann TypeScript die css-Eigenschaft nicht auflösen und meldet den folgenden Fehler:

TS2322: Type '{ children: string; css: SerializedStyles; }' is not assignable to type 'DetailedHTMLProps<HTMLAttributes<HTMLDivElement>, HTMLDivElement>'.   Property 'css' does not exist on type 'DetailedHTMLProps<HTMLAttributes<HTMLDivElement>, HTMLDivElement>'.

create-react-app (CRA)

npx create-react-app emotion-hello --template typescript
cd emotion-hello
pnpm i @emotion/react

Wichtigste Abhängigkeitsversionen

{
  "react": "^18.1.0",
  "react-dom": "^18.1.0",
  "react-scripts": "5.0.1",
  "typescript": "^4.6.4",
  "@emotion/react": "^11.9.0"
}

Babel

Bei CRA ist die Babel-Konfiguration recht starr; du kannst sie mit @craco/craco erweitern.

@craco/craco installieren
pnpm i @craco/craco -D
Die Datei craco.config.js erstellen und konfigurieren
module.exports = {
  babel: {
    presets: [
      [
        "@babel/preset-react",
        { runtime: "automatic", importSource: "@emotion/react" },
      ],
    ],
    plugins: ["@emotion/babel-plugin"],
  },
};

JSX Pragma

Beim Import einen Kommentar hinzufügen
/** @jsx jsx */
import { css, jsx } from "@emotion/react";

Daraufhin tritt folgender Fehler auf:

 pragma and pragmaFrag cannot be set when runtime is automatic.
Lösung 1
+ /** @jsxRuntime classic */
/** @jsx jsx */
Lösung 2

- /** @jsx jsx */

Fazit

Konfiguriere Emotion am besten über Babel.

css prop

An den Typdeklarationen siehst du die Funktionsüberladungen: Die css-Methode lässt sich auf zwei Arten aufrufen.

export function css(
  template: TemplateStringsArray,
  ...args: Array<CSSInterpolation>
): SerializedStyles;

export function css(...args: Array<CSSInterpolation>): SerializedStyles;

Template-Strings

Der css-Methode kannst du direkt einen Template-String übergeben.

Das style hier entspricht exakt einem Inline-Style oder Styles aus einer Styledatei.

Diese Schreibweise entspricht eher der Art, wie wir Styles normalerweise schreiben.

import { css } from "@emotion/react";

<div
  css={css`
    padding: 32px;
    background-color: hotpink;
    font-size: 24px;
    border-radius: 4px;
    &:hover {
      color: ${color};
    }
  `}
/>;

Object

import { css } from "@emotion/react";

const color = "white";

<div
  css={css({
    padding: 20,
    backgroundColor: "hotpink",
    fontSize: 24,
    borderRadius: 4,
    "&:hover": {
      color,
    },
  })}
/>;

Der css-Eigenschaft kannst du direkt ein Objekt übergeben, ohne die css-Methode aufzurufen.

import { css } from "@emotion/react";

const color = "white";

<div css={{
    padding: 20,
    backgroundColor: "hotpink",
    fontSize: 24,
    borderRadius: 4,
    "&:hover": {
        color,
    },
}}>

Rückgabewert der Methode

export interface SerializedStyles {
  name: string;
  styles: string;
  map?: string;
  next?: SerializedStyles;
}
  • name ist der Klassenname (standardmäßig wird das Präfix css ergänzt)
  • styles: der eigentliche Style
  • map: die Sourcemap

Priorität von Styles

import { CSSObject } from "@emotion/react";

interface PProps {
  css?: CSSObject;
}

function P(props: PProps) {
  return (
    <p
      css={{
        margin: 0,
        fontSize: 12,
        lineHeight: 1.5,
        fontFamily: "sans-serif",
        color: "black",
      }}
      {...props}
    />
  );
}
export default function ArticleText() {
  return (
    <P
      css={{
        fontSize: 14,
        fontFamily: "Georgia, serif",
        color: "darkgray",
      }}
    />
  );
}

Ergebnis von ArticleText

Das entspricht einer Zusammenführung der Styles. Gemäß der „Order of Appearance“-Regel der css-Spezifikation überschreiben später definierte Eigenschaftswerte (grün) früher definierte (rot).

.css-kcvhz8-P-ArticleText {
    margin: 0;
-    font-size: 12px;
    line-height: 1.5;
-    font-family: sans-serif;
-    color: black;
+    font-size: 14px;
+    font-family: Georgia,serif;
+    color: darkgray;
}

Fazit

Die über props übergebene css-Eigenschaft hat Vorrang vor der css-Eigenschaft innerhalb der Komponente. So kannst du beim Aufruf der Komponente deren Standard-Styles überschreiben.

Styled Components

Gestylte Komponenten.

styled ist eine Möglichkeit, React-Komponenten zu erstellen und Styles an sie zu binden; inspiriert wurde es von styled-components und glamorous.

Abhängigkeiten installieren

pnpm i @emotion/styled

Gestylte Komponenten erstellen

Template-Strings

Eine Button-Komponente erstellen

import styled from "@emotion/styled";

const Button = styled.button`
  color: red;
  width: 200px;
  height: 50px;
`;

<Button>Hello styled components</Button>;

Object

Eine div-Container-Komponente erstellen

import styled from "@emotion/styled";

const Container = styled.div({
  color: "red",
  width: 1200,
  backgroundColor: "blue",
  margin: "0 auto",
});

<Container>
  <Button>Hello styled components</Button>
</Container>;

Standard-Styles innerhalb gestylter Komponenten überschreiben

Template-Strings

import styled from "@emotion/styled";

const Button = styled.button`
  width: 200px;
  height: 50px;
  color: ${(props) => props.color || "red"};
`;

<Button>默认颜色</Button>
<Button color="green">更改颜色</Button>

Object

Hier wird das gesamte Argument als Funktion übergeben.

import styled from "@emotion/styled";

export const Container = styled.div((props: { backgroundColor?: string }) => ({
  color: "red",
  width: 1000,
  backgroundColor: props.backgroundColor || "blue",
  margin: "0 auto",
}));

Das erste Argument ist ein Objekt, das zweite eine Funktion.

export const Container = styled.div(
  {
    color: "red",
    width: 1000,
    margin: "0 auto",
  },
  (props: { backgroundColor?: string }) => ({
    backgroundColor: props.backgroundColor,
  }),
);

Styles für beliebige Komponenten hinzufügen

styled akzeptiert jede Komponente und ergänzt sie um eine className-Eigenschaft (eigentlich ist das nur der von der css-Methode erzeugte className).

const Basic = ({ className }: { className?: string }) => (
  <div className={className}>Some Text</div>
);

Template-Strings

import styled from "@emotion/styled";

export const Fancy = styled(Basic)`
  color: hotpink;
`;

<Fancy />;

Object

import styled from "@emotion/styled";

export const Fancy = styled(Basic)({
  color: "hotpink",
});

<Fancy />;

Stile von Kindkomponenten über die Elternkomponente festlegen

Template-Strings

import styled from "@emotion/styled";

export const Child = styled.div`
  color: red;
`;

export const Parent = styled.div`
  ${Child} {
    color: green;
  }
`;

<Parent>
  <Child>Green because I am inside a Parent</Child>
</Parent>
<Child>Red because I am not inside a Parent</Child>

Nur ein Child innerhalb eines Parent wird grün.

Object

import styled from "@emotion/styled";

const Child = styled.div({
  color: "red",
});

// TS2464 a computed property name must be of type 'string', 'number', 'symbol', or 'any'.
// https://github.com/emotion-js/emotion/issues/1275#event-6533934489
const Parent = styled.div({
  [Child as any]: {
    color: "green",
  },
});

<Parent>
  <Child>Green because I am inside a Parent</Child>
</Parent>;
<Child>Red because I am not inside a Parent</Child>;

Verschachtelte Komponenten

Mit dem verschachtelten Selektor & (der die Komponente selbst bezeichnet):

import styled from "@emotion/styled";

export const Nesting = styled.span`
  color: lightgreen;
  & > a {
    color: hotpink;
  }
`;

<Nesting>
  This is <a>nested</a>
</Nesting>;

Manchmal lässt sich & auch im Selektor eines anderen Elements verwenden; in bestimmten Szenarien ist das nützlich.

const paragraph = css`
  color: turquoise;

  header & {
    color: green;
  }
`;
render(
  <div>
    <header>
      <p css={paragraph}>This is green since it's inside a header</p>
    </header>
    <p css={paragraph}>This is turquoise since it's not inside a header.</p>
  </div>,
);

as

Alias

Wenn du die Styles einer gestylten Komponente weiterverwenden, aber das gerenderte Element-Tag ändern möchtest, nutzt du die as-Eigenschaft.

import styled from "@emotion/styled";

const Button = styled.button`
  color: hotpink;
`;

<Button as="a">Emotion as props</Button>;

Style-Komposition

import { css } from "@emotion/react";

const danger = css`
  color: red;
`;

const base = css`
  background-color: darkgreen;
  color: turquoise;
`;

export const Composition = () => (
  <div>
    <div css={base}>This will be turquoise</div>
    <div css={[danger, base]}>
      This will be also be turquoise since the base styles overwrite the danger
      styles.
    </div>
    <div css={[base, danger]}>This will be red</div>
  </div>
);

<Composition />;

Du kannst den Wert einer css-Variablen auch direkt an eine andere css-Variable übergeben.

const base = css`
  color: hotpink;
`

render(
  <div
    css={css`
      ${base};
      background-color: #eee;
    `}
  >
    This is hotpink.
  </div>
)

Priorität

Bei der Style-Komposition hängt die wirksame Reihenfolge von der Aufrufreihenfolge der Styles ab, nicht von ihrer Deklarationsreihenfolge.

Media Queries

Die Verwendung von media queries in Emotion ist identisch mit der in CSS.

Template-Strings

<p
  css={css`
    font-size: 30px;
    @media (min-width: 420px) {
      font-size: 50px;
    }
  `}
>
  Some text!
</p>

Object

<p
  css={css({
    fontSize: 30,
    "@media (min-width: 420px)": {
      fontSize: 50,
    },
  })}
>
  Some text!
</p>

Wiederverwendbare Media Queries

Mit definierten breakpoints lassen sich ganz einfach responsive Layouts erstellen.

import { jsx, css } from "@emotion/react";

const breakpoints = [576, 768, 992, 1200];

const mediaQueries = breakpoints.map((bp) => `@media (min-width: ${bp}px)`);

render(
  <div>
    <div
      css={{
        color: "green",
        [mediaQueries[0]]: {
          color: "gray",
        },
        [mediaQueries[1]]: {
          color: "hotpink",
        },
      }}
    >
      Some text!
    </div>
    <p
      css={css`
        color: green;
        ${mediaQueries[0]} {
          color: gray;
        }
        ${mediaQueries[1]} {
          color: hotpink;
        }
      `}
    >
      Some other text!
    </p>
  </div>,
);

Media Queries mit facepaint vereinfachen

pnpm i facepaint
pnpm i @types/facepaint
const breakpoints = [576, 768, 992, 1200];
const mq = facepaint(breakpoints.map((bp) => `@media (min-width: ${bp}px)`));
<div
  css={mq({
    color: ["green", "gray", "hotpink"],
  })}
>
  Some text.
</div>;

Global

Globale Styles

Du kannst mehrere Global-Styles definieren.

styles kann ein Objekt oder ein Template-String sein.

import { css, Global } from "@emotion/react";

<Global
  styles={css`
    .some-class {
      color: hotpink;
    }
  `}
/>
<Global
  styles={{
    body: { margin: 0 },
    a: { textDecoration: "none", color: "red" },
    ".some-class": {
      fontSize: 50,
      textAlign: "center",
    },
  }}
/>
<a>This is red</a>
<div className="some-class">This classname is .some-class</div>

Keyframes

Mit keyframes lassen sich Animationen definieren.

import styled from "@emotion/styled";
import { keyframes } from "@emotion/react";

const rotate = keyframes`
  from {
    transform: rotate(0deg);
  }
  to {
    transform: rotate(360deg);
  }
`;

export const Rotate = styled.div`
  display: inline-block;
  animation: ${rotate} 2s linear infinite;
  padding: 2rem 1rem;
  font-size: 1.2rem;
`;
<Rotate>😄</Rotate>

theming

Das Theme wird über den Kontext bereitgestellt; alle Kindkomponenten haben Zugriff darauf.

import { ThemeProvider } from "@emotion/react";

const theme = {
  colors: {
    primary: "hotpink",
  },
};

Theme-Typ deklarieren

Standardmäßig ist theme ein leeres Objekt. In einer TypeScript-Umgebung führt das zu einem Fehler, sobald die entsprechenden Eigenschaften fehlen.

Datei emotion.d.ts erstellen:

import "@emotion/react";

declare module "@emotion/react" {
  export interface Theme {
    color: {
      primary: string;
      positive: string;
      negative: string;
    };
  }
}

tsconfig.json anpassen.

  "include": [
    "src",
+    "emotion.d.ts"
  ]

css prop

Über die css-Eigenschaft auf das Theme aus dem Kontext zugreifen.

import { ThemeProvider } from "@emotion/react";

const CSSProp = () => {
  return (
    <div css={(theme) => ({ color: theme.colors.primary })}>
      some other text
    </div>
  );
};

const theme = {
  colors: {
    primary: "hotpink",
  },
};

<ThemeProvider theme={theme}>
  <CSSProp />
</ThemeProvider>;

styled

import styled from "@emotion/styled";

const Styled = styled.div`
  color: ${(props) => props.theme.colors.primary};
`;

<ThemeProvider theme={theme}>
  <Styled>some other text</Styled>
</ThemeProvider>;

useTheme

import { ThemeProvider, useTheme } from "@emotion/react";

export const Hook = () => {
  const theme = useTheme();
  return <div css={{ color: theme.colors.primary }}>some other text</div>;
};

const theme = {
  colors: {
    primary: "hotpink",
  },
};

<ThemeProvider theme={theme}>
  <Hook />
</ThemeProvider>;

Mehrere Themes zusammenführen

import { ThemeProvider, withTheme } from "@emotion/react";

const theme = {
  backgroundColor: "green",
  color: "red",
};

const adjustedTheme = (ancestorTheme) => ({ ...ancestorTheme, color: "blue" });

<ThemeProvider theme={theme}>
  <ThemeProvider theme={adjustedTheme}>
    <Text>Boom shaka laka!</Text>
  </ThemeProvider>
</ThemeProvider>;

Label

Hänge dem className ein Suffix an, um die Lesbarkeit zu verbessern.

import { css, jsx } from "@emotion/react";

let style = css`
  color: hotpink;
  label: some-name;
`;

let anotherStyle = css({
  color: "lightgreen",
  label: "another-name",
});

let ShowClassName = ({ className }) => (
  <div className={className}>{className}</div>
);

<div>
  <ShowClassName css={style} />
  <ShowClassName css={anotherStyle} />
</div>;

Den Testergebnissen zufolge kommt lediglich ein Label-Name hinzu

// 默认情况
css-1gfxf27-style
css-5pgj1t-anotherStyle
// 添加label
css-wxo79j-some-name-style
css-1i0m745-another-name-anotherStyle

ClassNames

Erzeugt einen className und übergibt ihn an Kindkomponenten – in React entspricht das einem render props-Muster.

import { ClassNames } from "@emotion/react";

let SomeComponent = (props: any) => (
  <div className={props.wrapperClassName}>
    in the wrapper!
    <div className={props.className}>{props.children}</div>
  </div>
);

<ClassNames>
  {({ css }) => (
    <SomeComponent
      wrapperClassName={css({ color: "green" })}
      className={css`
        color: hotpink;
      `}
    >
      from children!!
    </SomeComponent>
  )}
</ClassNames>;

Nur ein über ClassNames erhaltenes css erzeugt einen className.

Attaching Props

Wenn du css an eine gewöhnliche React-Komponente anhängst, hat das css in den props Vorrang vor dem css innerhalb der Komponente.

Das entspricht dem Beispiel im Abschnitt zur Style-Priorität.

CacheProvider

Abhängigkeiten installieren

pnpm i @emotion/cache stylis
pnpm i @types/stylis -D
import { CacheProvider, css } from "@emotion/react";
import createCache from "@emotion/cache";
import { prefixer } from "stylis";

const customPlugin = () => {};

const myCache = createCache({
  key: "my-prefix-key",
  stylisPlugins: [
    customPlugin,
    // has to be included manually when customizing `stylisPlugins` if you want to have vendor prefixes added automatically
    prefixer,
  ],
});

<CacheProvider value={myCache}>
  <div
    css={css`
      display: flex;
      width: 80px;
    `}
  >
    <div
      css={css`
        flex: 1;
        transform: scale(1.1);
        color: hotpink;
      `}
    >
      Some text
    </div>
  </div>
</CacheProvider>;

In diesem Fall dient my-prefix-key als Präfix der CSS-Klasse und ersetzt das Standardpräfix css.

Fallback

Fallback-Mechanismus

Der Wert wird als Array definiert: Unterstützt der Browser linear-gradient nicht, wird auf red zurückgegriffen.

<div
  css={{
    background: ["red", "linear-gradient(#e66465, #9198e5)"],
    height: 100,
  }}
/>

Komposition

css-Werte lassen sich aneinander weiterreichen.

const hotpink = css({
  color: "hotpink",
});

const hotpinkHoverOrFocus = css({
  "&:hover,&:focus": hotpink,
});

const hotpinkWithBlackBackground = css(
  {
    backgroundColor: "black",
    color: "green",
  },
  hotpink,
);

Fazit

  1. Die Entwicklungserfahrung ist ordentlich – Code-Vervollständigung funktioniert auch ohne installiertes Plugin; nur die Konfiguration ist etwas aufwendig.

  2. Dem Eindruck nach umfasst Emotion die Funktionen von styled-components, während styled-components derzeit ebenfalls alle Funktionen von Emotion abdeckt.

  3. React unterstützt von Haus aus inline styles, Emotion ebenfalls. Es erweitert jedoch die JSX-Syntax um eine css prop und ermöglicht so komplexere Styles. Genau darin liegt aber auch sein Nachteil: Es verändert React.
