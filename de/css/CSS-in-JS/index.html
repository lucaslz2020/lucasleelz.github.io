CSS-in-JS

Warum CSS-in-JS existiert, wie es funktioniert und wann es sich lohnt – ausgehend vom Prinzip der Trennung von Zuständigkeiten.

Traditionelle Entwicklung

In der Webentwicklung werden CSS, HTML und JavaScript üblicherweise voneinander getrennt.

HTML ist für die Struktur einer Webseite verantwortlich.

CSS ist für das Styling (die visuellen Effekte) der einzelnen Elemente einer Webseite verantwortlich.

JavaScript ist für die Interaktion (die Logik) zwischen Webseite und Nutzer verantwortlich.

Dieses Designprinzip – ein Computerprogramm in verschiedene Teile zu zerlegen – nennt man Trennung von Zuständigkeiten (Separation of Concerns, kurz SoC). Die Trennung von HTML, CSS und JavaScript ist eine typische Anwendung dieses Prinzips.

Was ist CSS-in-JS?

CSS-in-JS ist eine Styling-Technik, bei der CSS mit JavaScript geschrieben wird – CSS wird also in JavaScript integriert. Das wirkt zunächst kontraintuitiv.

Wird dieser JavaScript-Code ausgeführt, erzeugt er CSS (in der Regel als <style>-Element) und fügt es dem DOM hinzu.

Warum CSS-in-JS?

In der traditionellen Entwicklung werden CSS-Dateien meist direkt in HTML eingebunden. Da Styles keinen isolierten Scope haben, überschreiben sie sich leicht gegenseitig.

Moderne Entwicklung ist zunehmend komponentenbasiert – Styles sollen innerhalb der Komponentengrenzen wirken. Genau das leistet CSS-in-JS: Styles werden dort verwaltet, wo sie verwendet werden, statt ungewollt auf andere Komponenten überzugreifen.

Lösung des Scope-Problems

Mit CSS-in-JS wird der JavaScript-Scope genutzt, um einen CSS-Scope zu simulieren. CSS erhält so einen eigenen, isolierten Scope: Styles können nicht aus der Komponente nach außen gelangen, Stilkonflikte werden vermieden und Styles wirken nur innerhalb der Komponente. Damit ist das Problem gelöst, dass CSS keinen Scope besitzt.

Mehr Unabhängigkeit und Portabilität für Komponenten

Beim Verschieben einer Komponente vergisst man leicht die zugehörige Style-Datei – oder weiß gar nicht, wo sie liegt. Mit CSS-in-JS ist die Komponente eine eigenständige Datei: Man verschiebt nur die Komponente selbst, und sie funktioniert sofort. So lassen sich lose gekoppelte Anwendungen mühelos erstellen.

Wiederverwendbarkeit

Einmal geschrieben, überall lauffähig: Komponenten lassen sich nicht nur in derselben Anwendung wiederverwenden, sondern auch in anderen Anwendungen, die mit demselben Framework erstellt wurden.

Dynamik

CSS ist nicht dynamisch – Styles lassen sich nicht bedingt auf ein Element anwenden. Mit CSS-in-JS nutzt man die dynamischen Fähigkeiten von JavaScript, um Elementen Styles zur Laufzeit zuzuweisen, sodass auch komplexe Logik auf Style-Regeln angewendet werden kann. Gerade für komplexe, dynamische UIs ist das die ideale Lösung.

On-Demand-Importe

Je größer die Anwendung wird, desto größer werden auch ihre Komponenten – daher müssen sie on demand importiert werden. Mit CSS-in-JS lässt sich das mithilfe von tree-shaking einfacher umsetzen.

Kurz gesagt: CSS-in-JS behebt die Einschränkungen von CSS – etwa fehlende dynamische Fähigkeiten, fehlenden Scope und mangelnde Portabilität.

Zusammenfassung

Es eignet sich besonders für den Einsatz in Komponentenbibliotheken.

CSS-in-JS ist lediglich ein Pattern, das vom Framework unterstützt werden muss.

Gängige Frameworks sind:

  • Emotion
  • Styled Components
  • JSS
